# Agent Note: 有界配置采样

Status: implemented

[English](2026-09-08-bounded-config-polling.md) | 中文

## Problem

原生订阅启动可能遗漏注册之后创建的配置。Chokidar 轮询也没有明确拥有初始异步 stat 基线：在线程池争用下，注册之后的创建可能成为该基线并一直无法被发现。

## Decision

精确配置采样拥有并等待初始目标 stat，随后通过一个不重叠的定时器比较 bigint 指纹。它不执行周期性目录扫描或订阅。显式原生模式和模块监听保留各自实现。[就绪决策](../../../../docs/decisions/20260908-config-watch-readiness.zh.md) 负责记录证据、支持的选项和祖先目录持续存在的条件。

原始文件系统操作、清理和采样错误通知分别拥有完成状态。清理等待原始 I/O 和已经接纳的刷新，而错误监听器可以等待清理，不会形成自我等待。连续等价的采样错误会去重，但不会替换上一次成功观测。

## Alternatives considered

**Chokidar 轮询就绪。** 它的隐式初始基线可能吸收 ready 事件之后的持久变化。

**原生启动补扫。** 单次扫描无法覆盖持续到扫描结束之后的操作系统订阅间隙。

**生产哨兵写入。** 哨兵会引入无关的文件系统写入和权限要求。

## Consequences

采样观察持久状态，而非每次中间编辑。每周期一次目标 stat 使周期性工作量不受同级条目数量影响；初始规范化解析仍会遍历祖先。回调失败不会自动重试刷新。在上游提供等效行为之前，供应商同步必须保留这些基线与释放回归测试。
