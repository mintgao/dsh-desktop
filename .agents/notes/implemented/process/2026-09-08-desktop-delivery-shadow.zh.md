# Agent Note: 发布前的桌面交付证据

Status: implemented

[English](2026-09-08-desktop-delivery-shadow.md) | 中文

## 问题

上游发现、源码采用和桌面发布的失败及批准要求不同。版本查询成功不能证明采用检出能够构建、安装包后端能够启动，或两种桌面架构包含同一候选。在验证这些关系前更换生产写入者，可能用另一种不透明失败替换原有失败。

## 决策

[经审查交付工具](2026-09-08-reviewed-desktop-release-delivery.zh.md) 具有独立生产资格验证和启用要求。试运行证据保留不提供授权的用途。

[试运行 CLI](../../../../scripts/desktop-delivery/cli.ts) 和[手动工作流](../../../../.github/workflows/desktop-delivery-shadow.yml) 生成有版本、未签名且没有发布权限的证据。显式发行版配置使 Mint 身份独立于可复用验证逻辑。完整版本观察结果与已记录身份核对；源码检查先于打包；文件摘要和挂载后端冒烟将每种架构绑定到候选。汇总独立核对下载证据，要求全部配置架构。

[试运行决策](../../../../docs/decisions/20260908-desktop-delivery-shadow.zh.md) 规定确切验证与原生冒烟要求。[操作指南](../../../../docs/cookbook/desktop-delivery-shadow.zh.md) 负责本地发现命令。现有[生产采用](2026-08-27-automatic-upstream-desktop-releases.zh.md) 和[签名策略](2026-08-27-pre-certificate-unsigned-desktop-previews.zh.md) 继续生效；此附加工作流不取代其写入者或控制。

## 考虑过的替代方案

**在安装包证据存在前替换生产写入者。** 新的批准模型不能证明打包后端启动或架构完整性。只读验证在不改变发布状态的情况下暴露这些失败。

**把 Electron 启动加载视为完整启动测试。** 启动加载命令在后端启动前退出。需要挂载后端启动才能验证打包运行时及带认证的 HTTP 就绪。

**把有修改的本地检出视为确切提交的合格证据。** 提交身份不包含本地修改。有修改检出报告只能作为诊断；验证合格要求干净工作流证据。

## 影响

维护者可以在本地复现发现与安装包失败，在生产迁移前查看统一摘要。附加工作流消耗原生构建时间，但不能创建采用 PR 或发布版本。未签名证据不能证明发布者身份或已安装客户端替换。单一原生架构不能证明双架构成功，所有试运行报告均不授权发布。
