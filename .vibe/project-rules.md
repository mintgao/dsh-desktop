# Project-specific rules

All current and future downstream work must follow [DSH downstream development policy](../docs/context/downstream-policy.md). Read it before shaping, designing, implementing, or reviewing a requirement; it owns product scope, plugin placement, external reuse, compatibility, and update acceptance.

Desktop releases must follow the [homepage maintenance rule](../README.md#homepage-maintenance): the release owner synchronizes both README languages and their pairing record for published key features, important fixes, and support or installation changes before claiming release completion. The [homepage decision](../.agents/notes/implemented/process/2026-09-13-mint-homepage-maintenance.md) records the rationale.

Machine handoffs follow [Desktop Mint handoff](../docs/context/handoff.md), preserving source authority, private data boundaries, release evidence and post-installation acceptance.
