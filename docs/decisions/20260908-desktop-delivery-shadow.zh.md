## 依据与范围

实现[交付提案](20260908-desktop-update-delivery.zh.md) 的第二迁移阶段：可执行发现、候选验证、未签名打包证据及维护者摘要。[二次开发规范](../context/downstream-policy.zh.md) 约束复用。现有生产工作流、策略证明、凭证和状态继续生效，保持不变。

本决策授权本地输出和选择启用的工作流摘要与产物。不引入采用写入者、发布操作、通知发送者、签名任务、调度器或生产批准回执。生产信任模型替换仍未决定，不属于本决策。

## 可执行工具

在 `scripts/desktop-delivery/cli.ts` 增加一个源码侧 CLI（命令行界面），根命令为 `desktop:delivery`。解析、GitHub 读取、候选验证与产物核对放在相邻小模块中，配备行为测试。每个导出操作都必须由 CLI 命令或工作流执行，不构建未使用的发布框架。

使用显式 JSON 发行版配置，指定上游仓库、发布标签选择和必需架构。Mint 值放在配置文件中，不进入通用验证逻辑。仓库拥有的打包命令是固定命令，不能由配置提供可执行字符串。

- `discover`：读取配置和基线或源码锁定输入，查询全部上游公开版本分页并将标签解析为提交，或读取等价离线 fixture（测试前置数据）。输出有序观察结果和 `next`、`current` 或 `blocked`。区分不完整或 API 失败与没有更新。相同重复身份去重；冲突重复、标签变化、已记录身份缺失和意外更早版本都会阻塞。发现只写请求的本地输出。
- `candidate`：根据检出的下游提交和上游祖先关系验证显式源码锁定输入，并记录发行版身份、确切组件版本及源码记录摘要。打包前运行现有 workspace 依赖与版本检查。已发现版本不是已采用候选；缺少匹配源码证据时阻止打包。
- `artifact`：计算单架构 DMG 摘要，将大小、摘要、候选摘要及冒烟证据绑定到架构报告。
- `combine`：独立重新计算已下载文件摘要，要求架构集合与配置完全一致、候选身份匹配且必需冒烟证据成功。生成组合试运行 manifest（元数据清单）和维护者摘要。

源码锁定记录包含上游仓库、Release ID、发布时间、标签、提交和前序身份。本阶段验证所提供记录并生成拟议本地输出，不建立生产采用历史，也不自动修改已提交记录。

报告使用有版本的 schema，明确标记 `purpose: desktop-delivery-shadow`、`signing: unsigned` 和 `publicationEligible: false`。摘要绑定确切序列化证据字节。拒绝畸形字段、重复文件、不安全路径、逃出产物目录的符号链接、缺失证据和文件字节变化。这些报告不能作为最终生产验证。

## 工作流与打包证据

只新增由 `workflow_dispatch` 触发的 `.github/workflows/desktop-delivery-shadow.yml`。检出与报告候选身份固定为派发的 `GITHUB_SHA`，不接受任意候选检出 ref。使用 `permissions: contents: read`，不使用受保护环境、App 或 Apple 秘密、持久检出凭证，也不读取生产状态。工作流产物上传和任务摘要是仅有的远程输出。

提供明确的仅发现与未签名验证两种模式。验证使用同一检出中的源码证据；缺失或不一致则阻塞。发现更新版本不妨碍验证单独标识的当前检出。

使用原生 `macos-15` arm64 与 `macos-15-intel` x64 任务、冻结依赖安装和现有 `desktop:stage` 路径。electron-builder 明确选择未签名、关闭公证并使用 `--publish never`。保留现有打包布局与应用行为。

执行 `--dsh-package-smoke`，将结果标为 Electron 启动加载冒烟：当前命令在后端启动前退出。增加仅供测试的打包后端冒烟脚本，通过打包 Electron 的 Node 模式、现有 `BackendSupervisor`、`desktop-mint` 和标准就绪解析器启动暂存 CLI。使用临时工作区和 DSH home、没有用户凭证的允许列表环境，以及保证有界完成的清理。要求回环就绪、本地 HTTP 响应成功及进程终止。这证明打包后端可启动，不证明已安装客户端行为。

将每个 DMG 只读挂载，定位唯一预期应用，对该打包载荷执行冒烟，并在 `finally` 中卸载。从原生可执行文件记录架构，不能信任文件名。不把应用复制到用户安装目录。

只有汇总任务组合两种架构。失败或缺失任一架构不能产生成功。日志和部分证据仍作为有用的失败输出保留。

## 摘要、重试与复用

摘要说明候选、观察到的上游版本、完成检查、阻塞和维护者下一步。成功输出称为试运行预览检查通过，绝不称为可发布。在本地和工作流摘要中生成可用于通知的 Markdown；不发送通知，不声称 GitHub 或邮件已送达。

GitHub 读取对已分类暂时失败最多尝试三次，采用有界退避和有限请求及任务超时。认证、畸形证据和身份冲突立即失败。打包与冒烟失败不自动重试。维护者修正原因后明确重跑；新尝试产生新证据。

通过第二份发行版配置和可执行 fixture 运行证明复用。本阶段不需要抽取原生包：新工作流是可复用交付工具的真实消费方，现有桌面管理器由自身测试工具复用。

## 恢复与限制

失败不改变生产状态。修正后删除本地输出或重新验证。试运行产物按工作流保留期过期，不能建立持久发布权限。现有安装和 DSH 数据保持不变。

本地工作树有修改时必须记录源码差异，且只能产生不合格诊断；CI 成功要求确切干净检出。单一本地架构不能证明双架构成功。未签名冒烟不能证明 Developer ID 身份、公证、通知送达、已安装应用替换或持久数据迁移安全。

## 实现验收

### 带认证信息的桌面就绪地址修订

Web Bundle 输出 `connection.authenticatedUrl(...)`；BrowserAuth 生成带单个 `token` 参数的根地址。桌面解析器目前拒绝斜杠与查询参数，同时记录原始就绪行。仅修改 `apps/desktop/src/backend.ts`、相关测试、`apps/desktop/src/main.ts` 的启动错误脱敏调用及受影响文档。保留进程所有权、超时和有界关闭。

解析精确 `dsh web: ` 前缀后的第一个完整 URL，为 `BrowserWindow.loadURL` 保留令牌。要求字面形式的 `http://127.0.0.1`、1 至 65535 的显式十进制端口、无凭证、根路径及无片段。接受无查询参数或恰好一个非空 `token` 参数。拒绝规范化技巧、意外路径、额外或重复参数及畸形 URL，不从流回调抛出异常。保留无令牌就绪行及可选尾随 LAN 注释；LAN 地址不决定就绪。

在日志回调、诊断保留和启动错误展示前对认证查询值脱敏，包括 stderr、畸形就绪行和 LAN 注释。仅在内存解析原始输入；认证 URL 只作为临时启动输入。后端诊断和 `reportStartupFailure` 复用同一个范围有限的脱敏函数。

SH-7 要求使用合成令牌测试接受与拒绝的 URL、跨子进程输出块的认证就绪行、干净退出，以及日志、超时或早退错误、意外退出诊断和启动错误展示中不含令牌。通过修复后的管理器重跑真实 ARM64 DMG 冒烟，保留认证 URL。这仍属于打包后端证据，不是安装或签名发布验证。

- SH-1：CLI fixture 和模拟分页 HTTP 测试覆盖排序、重复、缺失或变化身份、不完整获取及暂时失败重试耗尽。
- SH-2：实际候选命令在调用打包前拒绝源码不匹配和 workspace 版本不一致。
- SH-3：可执行产物测试拒绝字节变化、错误可执行架构、缺少冒烟证据，以及任一架构缺失或失败。
- SH-4：工作流测试验证触发器、权限、固定检出、未签名命令及不存在仓库变更，同时证明工作流确实调用已实现 CLI。
- SH-5：两份配置执行相同 CLI；摘要准确区分已发现、阻塞和试运行验证通过，不要求组件更新选择。
- SH-6：RD 执行针对性检查及可行本地打包冒烟。独立 QA 负责最终验收和未变化候选的配置默认验证。未运行的原生架构及远程工作流执行明确保留为限制。

实现所有权范围为 `scripts/desktop-delivery/**`、新工作流、配置与 fixture、根命令接线、必需文档及明确限定的认证就绪修订。其他原生应用或生产工作流修改必须重新开启本决策。
