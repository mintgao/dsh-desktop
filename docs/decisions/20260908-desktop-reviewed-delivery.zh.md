## 依据与可执行范围

通过 `desktop:delivery` 实现普通采用、未签名原生验证及显式批准发布。[交付设计](20260908-desktop-update-delivery.zh.md#owner-confirmation) 记录所有者已解决的 GitHub 保护信任选择；[二次开发规范](../context/downstream-policy.zh.md) 约束复用。管理员是信任根。现有生产控制持续生效，直到切换获验证。不引入自定义 App、续期策略证明、队列控制器或可变状态 ref。签名模式以 `signed-mode-unconfigured` 拒绝；试运行报告仍不能发布。

在 `scripts/desktop-delivery/` 扩展内聚的采用、生产清单、GitHub 操作及迁移模块。发行版值保留于 `.github/desktop-delivery/mint.json`。新增三个手动工作流：`desktop-delivery-adopt.yml`、`desktop-delivery-qualify.yml` 和 `desktop-delivery-mutate.yml`。CLI 与工作流使用相同实现；测试注入 GitHub 传输，使用临时 Git 仓库与产物测试数据。

命令包括 `adoption-plan`、`adoption-prepare`、`adoption-apply`、`release-manifest`、`promotion-plan`、`prepare-publication`、`promote`、`withdraw`、`restore` 和 `migration-preflight`。远程写入要求显式 `--apply` 及已审查操作计划摘要。默认调用生成本地计划。发布变更要求已启用工作流上下文；本地维护者操作只准备确切标签与草稿，不发布。

## 采用与审查身份

有序发现从完整观察结果与已提交源码锁定中选择直接下一个上游身份。采用计划绑定该身份、确切下游基线、拟议分支及桌面版本；发现现有采用 PR 时报告它，而不重复创建。

准备流程创建隔离检出，把确切上游提交合并到确切下游基线，不在存在写入凭证时执行候选 hook 或脚本。冲突保留检出并生成报告，不自动解决或跳过。冲突经过审查解决后，无写入凭证的版本与依赖检查生成隔离种子提交及单独拟议源码锁定更新。上游父提交必须保留于合并历史；采用 PR 不得通过 squash 或 rebase 丢弃它。桌面未签名预览版本映射使用显式元数据，不重写全部 workspace 版本。

本地维护者以现有认证会话只推送确切种子分支，包括工作流文件变化，不创建 PR。`desktop-delivery-adopt.yml` 从受保护 `main` 执行可信工具，验证种子 SHA、祖先、前序和拟议锁定，创建以种子为唯一父提交的实质源码锁定提交。它不强推分支，并通过 `GITHUB_TOKEN` 创建 PR。远程移动或人为修改分支会阻塞。候选代码不在存在写入 token 时执行。

机器人同时是 PR 作者和最后推送者，因此所有者可以提供必需审查，无须削弱保护。后续人工修改要求经过验证的实质锁定最终提交；空提交不能伪造审查资格。启用要求允许 Actions 创建 PR，同时默认 token 权限仍只读。只有采用写入任务请求 `contents: write` 与 `pull-requests: write`，不批准或合并。所有者可能需要批准机器人 PR 的检查运行。工作流权限失败会阻塞，不能替换成所有者身份。[GitHub token 行为](https://docs.github.com/en/actions/concepts/security/github_token) 与 [Actions 权限](https://docs.github.com/en/rest/actions/permissions) 定义平台行为。

源码锁定 schema 版本 2 增加 `adoptionSeed: { commit, tree }`，标识最终提交之前已存在的分支头和树，不引用包含新锁定的提交。机器人要求远程头等于该提交，验证其树及上游祖先，并创建只修改源码锁定文件的单父最终提交。验证从 Git 对象核对这些关系。人工修复代码后，新种子更新此绑定，同时保留上游与前序身份。已匹配最终提交的重试不写入；其他远程移动会拒绝，不强推。后续人工推送使最终绑定失效，直到机器人验证新种子。

恢复回归覆盖机器人最终提交、人工代码修复、陈旧种子拒绝、修正种子最终提交及所有者审查资格。断言父提交与树绑定、只修改锁定、上游与前序不变，以及无写入重试。在线验收验证 GitHub 的实际最后推送者和所有者审查资格，不能仅检查提交作者文字。

## 验证与最终清单

验证从受保护 `main` 派发，其 `GITHUB_SHA` 标识可信编排工具。候选是单独的完整提交 SHA，必须可从受保护 `main` 到达、干净且符合源码锁定。候选代码运行时没有发布或 Apple 凭证。原生 arm64 与 x64 任务复用 `desktop:stage`、显式未签名 electron-builder 参数、架构检查、带认证后端冒烟及有界清理。在打包元数据中明确设置桌面版本，并与底层 DSH 版本分开验证产出应用版本。

每个原生任务还把只读挂载应用载荷复制到临时安装目录，执行打包启动加载及带认证后端检查，停止后删除临时安装。这验证复制和启动，不替换用户应用，也不证明完整原生窗口交互或现有用户数据兼容性。

独立 schema 使用 `purpose: desktop-release-qualification`，绑定仓库与发行版、`unsigned-preview` 模式、桌面版本与标签、上游身份、下游提交、源码锁定摘要、组件版本、可信工作流路径与提交、运行 ID 与尝试次数、前序标签与清单或已审查旧基线摘要、各架构 DMG 名称与大小及摘要、候选与原生证据摘要、发布说明摘要及数据兼容性说明摘要。不包含自身摘要；批准对确切序列化字节计算摘要。汇总要求双架构及全部证据。重新标记试运行报告、产物缺失或过期、字节变化及验证失败都会阻塞；重新验证要求重新批准。

发布说明和数据兼容性说明来自确切候选。说明标识持久格式变化、迁移与恢复证据及不支持的降级路径。缺少评估会阻塞发布。持久数据变化要求上层设计规定的独立迁移审查证据；临时安装冒烟不能替代。

## 批准、准备与发布

一个仓库级变更并发组覆盖发布、撤回和恢复，禁止取消正在执行的操作。工作流接受操作、清单摘要、验证运行 ID 与尝试次数及标签。只读准备任务解析确切产物包并展示计划。受保护环境批准绑定该运行的不可变输入。可信工具来自工作流提交处的受保护 `main`，不来自候选。依赖安装禁用生命周期脚本；下载应用或包不在存在写入 token 时执行。

保留仅维护者创建标签的限制，以及独立、无绕过的标签更新和删除保护；切换时移除旧 App 创建绕过权限。不假定内置 Actions 可绕过。对应变更工作流持有并发位置并等待环境批准时，本地 `prepare-publication` 验证在线工作流路径、待批准状态和计划摘要，再以现有维护者凭证创建或核对已批准确切不可变标签与空草稿。所有者随后批准同一次运行。已取消或完成的运行及不同计划会阻塞准备。匹配的孤立草稿只能在同一清单的新显式批准运行中恢复。[GitHub Release API](https://docs.github.com/en/rest/releases/releases) 说明改变工作流的提交为何需要这种 token 权限分离。

获批发布者使用 `contents: write`、`actions: read` 和发布状态所需的 `issues: write`，没有 Administration 权限、Apple 秘密或主分支绕过。它重新获取运行元数据和产物，验证仓库、工作流路径与提交、候选源码、成功尝试次数、完整文件及摘要。取得并发位置后，重新读取启用状态、源码锁定历史、Release、标签和前序证据。假设改变则阻塞。

发布者只上传、验证并公开现有匹配草稿，不创建标签或替换目标。允许上传缺失的匹配文件，包括清单和验证证据。标签、文件、说明或身份冲突会阻塞，不能覆盖。验证草稿后发布为未签名预发布，不包含稳定更新元数据，再下载验证公开字节。公开内容不匹配会撤回版本并记录阻塞。不明确写入响应须先读取服务器状态再决定是否重写。同一清单可恢复中断草稿或验证已公开版本，无须重新构建；不同字节要求新桌面版本。

撤回保留不可变标签和资产为草稿。恢复在发布前验证保留的确切字节。被撤回前序阻塞后续交付，直到恢复或被同一上游版本的独立合格替代版本取代。不会远程降级已安装客户端。

## 前序关系与基线

使用源码锁定 Git 历史和清单前序链接，不建立完成账本。前序证据缺失或冲突会阻塞。源码锁定的 `predecessor` 标识上一个已采用上游版本；清单的 `predecessor` 标识上一次桌面交付。两者不能无条件视为相等。

### 上游顺序与桌面交付顺序

每份清单声明 `releaseKind: upstream | desktop | replacement`：

- `upstream`：其上游身份是最后已验证交付的上游身份之后直接下一个已采用身份。源码锁定的上游前序匹配该上一个上游身份，不能跳过中间采用。
- `desktop`：其上游身份等于最后已验证交付的上游身份。保留源码锁定的上游前序；交付前序为最后已验证桌面清单或经过审查的旧基线。这允许仅桌面修复和独立验证的重新构建，而不捏造上游采用。发现更新的上游不阻止此类交付。
- `replacement`：其上游身份等于被替代的撤回版本。包含 `supersedes: { tag, manifestDigest }`；交付前序为撤回版本之前的已验证交付。保留源码锁定的上游前序，原样保留撤回清单。

新的桌面发布必须在 SemVer 优先级上严格大于所有保留的曾公开桌面版本，包括已撤回版本。仅构建元数据变化不足。标签必须未使用，恢复同一已批准清单除外。恢复保留原版本和字节。

替代只适用于尚无已公开后继的撤回版本。撤回已发布链中更早的版本会阻塞继续发布，需要恢复或单独审查的链恢复方案；替代不能丢弃后继。

### 可调用准备入口

`adoption-plan` 接受显式 `--kind upstream|desktop|replacement` 和桌面版本。桌面准备使用当前已交付上游身份，不合并上游。替代还要求确切撤回标签和清单摘要。两者均创建可审查的种子与源码锁定计划，不推进发现或上游采用。

对于同一上游的源码变化，机器人最终提交更新 `adoptionSeed.commit/tree`，保留上游版本及其前序。资格验证检查种子父提交与树关系。源码未变的重新构建可以复用有效最终提交，无须空洞提交。

`release-manifest` 和 `promotion-plan` 根据源码历史与在线交付关系验证声明类型。桌面版本更大不能推断上游已推进。

必需测试覆盖连续仅桌面发布、有新上游待处理时的桌面修复、此后真正的下一上游交付、拒绝跳过、同上游种子最终提交、撤回末端替代、拒绝存在已公开后继的替代、包括撤回版本的版本排序，以及确切清单重试。

旧 Release 没有新格式清单。迁移预检下载实际公开文件，验证校验和、标签、上游与源码来源及版本元数据，生成经过审查的 `legacy-baseline.json`，包含最后已完成上游身份、桌面标签、源码提交、保留产物摘要和旧证据引用。其确切摘要锚定新前序关系；不修改旧 Release 或捏造历史验证。基线还记录未解决采用；切换需核对该确切候选，否则保留为阻塞。

## 保护与唯一写入者启用

在线前提包括带必需检查和审查的 `main`、仅限受保护 `main` 且要求维护者审查的发布环境、具有受支持维护者创建权限的不可变桌面标签、已启用 Actions PR 创建、已验证机器人审查资格、发布 token 可访问已准备草稿，以及不存在旧变更权限。环境分支限制本身不足。[GitHub 环境](https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments) 定义平台语义。

初始未启用的 `activation.json` 绑定仓库 ID、基线摘要、迁移报告摘要、预期保护 ID 和工作流路径。经过审查的变更只有在在线切换证据存在后才能启用写入者。运行时读取可见保护字段，缺失或不匹配则拒绝；管理员检查记录 token 无法读取的字段。这是管理员证明，不是独立密码学策略证明。

预检列举控制器、观察者、最终处理者、验证、策略预检与引导、发布、撤回及已退役同步。启用前通过 GitHub 禁用全部旧入口和调度，排空或取消排队及运行任务，撤销 App 安装、凭证及尚存权限。旧撤回工作流具有独立 `github.token` 权限。仅删除秘密或改变布尔值不足。记录禁用工作流、完成或取消任务、撤销身份、保护和基线，并证明延迟回调不能变更。缺少证据则保持阻塞；保留旧状态和证明作为历史证据。

回退先禁用替代写入者。恢复旧机制要求有效前提，并核对每个替代发布。禁止竞争发布者。

### 管理员预检与运行时检查

`migration-preflight` 使用维护者已认证会话验证全部必需设置。`requireActivation` 验证已接受报告，并刷新其声明运行时 token 可执行的检查，不使用 `GITHUB_TOKEN` 重跑管理员预检。

可信代码固定仅管理员可见白名单：Actions 权限端点的 `default_workflow_permissions` 和 `can_approve_pull_request_reviews`、确切配置规则集 ID 中被省略的 `bypass_actors`，以及已有定义的旧权限撤销和在线验收证据。配置与运行时错误不能扩展该清单。GitHub 规定 [Actions 设置需要 Administration 读取权限](https://docs.github.com/en/rest/actions/permissions#get-default-workflow-permissions-for-a-repository) 和[绕过信息的受限可见性](https://docs.github.com/en/rest/repos/rules#get-a-repository-ruleset)。

每份证明记录固定检查标识、仓库 ID、资源 ID 或端点、观察时间、管理员身份、验证值和证据摘要。规则集证明还绑定运行时可见字段，包括 `updated_at`。摘要绑定的报告保留非秘密底层证据。启用绑定整份报告和发行配置，调用者不能替换独立管理员证据对象。

管理员预检必须成功获取 Actions 设置和完整规则集绕过信息。管理员读取失败不能由声明值替代。

运行时验证启用、报告与配置摘要及必需证明身份和值，不调用仅管理员可见的 Actions 权限端点。它重新获取仓库身份、可见规则集字段、发布环境保护和完整旧工作流与运行清单。

存在的 `bypass_actors` 必须通过验证并匹配证明。只有确切规则集身份及绑定可见字段仍匹配时，被省略的属性才能使用证明值。缺失不代表空列表。必需运行时读取的不匹配、不完整响应、意外缺字段、403、404 或网络重试耗尽均阻塞变更；通用权限错误不能授权回退。

每个执行运行时检查的任务显式获得 `actions: read`，包括通知和采用最终处理者，不授予 Administration 权限。环境与保护读取仍是必需，无法读取是在线阻塞。已知仅管理员可见设置改变时，需要刷新报告和经过审查的启用绑定。在已接受的管理员信任模型下，运行时不声称持续检测其无法读取的字段。

测试覆盖管理员读取失败、运行时不请求 Actions 权限端点、证明缺失或改变、省略绕过数据时的确切匹配证据、可见规则集漂移、公开绕过数据冲突和必需读取失败。有效运行时测试不需要 Administration 权限即可成功。

## 首次工作流引导

常规采用要求其工作流存在于受保护 `main`。已注册的 `desktop-ci.yml` 中的一次性模式允许从不可变、经过独立审查的实现快照安装。这明确例外于工具必须来自受保护 `main` 的要求，常规采用不能使用它。

维护者审查确切种子、工作流差异和源码锁定最终提交程序。专用非发布引导标签前缀在创建标签前具有更新与删除保护。不含秘密的引导环境要求所有者批准。所有者在不可变标签派发现有工作流，批准前核对仓库、工作流路径和运行头 SHA。这是所有者显式授权，不是独立代码审查。

引导跳过普通候选执行。任务仅使用 `contents: write` 和 `pull-requests: write`。它验证仓库 ID、不可变标签、种子与树、预期默认分支基线，并确认 `main` 尚无常规采用工作流。实现分支必须不存在、位于种子或匹配最终提交；竞争分支或 PR 会阻塞。单父最终提交只改变源码锁定，并实质绑定 `adoptionSeed`。它不强制更新，创建机器人署名 PR，并核对中断写入及无写入重试。

引导不能合并、发布、改变保护或凭证、派发工作流或编辑任意文件。只有下述专用非公开草稿权限探测可编辑其确切探测 Release 和资产。常规采用工作流存在于 `main` 后，引导拒绝继续执行。所有者通过必需检查和审查保护进行审查与合并。

当配置的源码锁定路径在确切受保护主分支引导基线中不存在时，引导使用 `baseLock: { state: "absent", baseCommit, path }` 和 `seedLockDigest`，后者是已审查不可变种子中锁定字节的 SHA-256。它从基线 Git 树证明缺失；API 错误或不可用对象不代表缺失。文件存在时要求普通前序锁定验证。

引导验证种子提交与树、预期受保护主分支基线、配置锁定路径、种子锁定摘要、受支持模式及发行与上游身份。上游提交必须是种子的祖先。种子锁定匹配显式引用的现有采用证据，例如固定的旧采用状态及已采用上游提交，而不是猜测版本或捏造基线。这只证明源码身份，不证明已完成发布，也不能替代生产迁移基线验证。

机器人生成模式 2 锁定，保留已审查种子锁定的上游版本、前序及观察，将 `adoptionSeed` 绑定到种子提交与树。单父最终提交只改变配置锁定文件。模式转换或种子绑定必须实质改变字节；否则返回已有确切最终提交或阻塞，不能创建空洞提交。

基线锁定缺失例外仅限已批准首次引导，且受保护 `main` 仍无常规采用工作流。常规采用仍要求已有基线锁定及摘要。旧采用证据缺失或不一致会阻塞引导。测试区分实际树缺失与查询失败，并覆盖已有锁定、种子字节变化、旧身份不匹配、不支持模式、上游祖先关系、模式转换、仅锁定最终提交及常规采用拒绝此例外。

测试覆盖不匹配引用、默认基线改变、已安装最终处理者、意外锁定修改、竞争分支或 PR、中断最终提交和匹配重试。在线验收验证标签保护、环境批准、实际机器人 PR 与最后推送者身份及所有者审查资格。缺失前提保持为上线阻塞；此决策本身不授权远程变更。

### 引导规则集可见性

经过审查的不可变 seed 保留 `.github/desktop-delivery/bootstrap-protection.json`：schema 版本 1、用途 `desktop-bootstrap-protection`、仓库及配置规则集 ID、观察时间、管理员数字 ID、空 `bypassActors`、观察到的规则集投影及摘要，以及保留的管理员响应证据的仓库相对路径和摘要。准备必须成功获得明确包含空 `bypass_actors` 的管理员响应；省略、格式错误或非空值不能生成证据。不保留凭据。

投影恰好包含 `id`、`source`、`source_type`、`target`、`enforcement`、`conditions`、`rules` 和 `updated_at`。规范 JSON 递归排序对象键并保留数组顺序，排除依请求者变化及展示字段。操作计划绑定证明文件摘要；运行时验证 seed 中的确切字节、schema、仓库、配置规则集、管理员及保留的响应证据。证明不包含自身所在 seed 的 SHA，以避免自引用；批准的计划和工作流绑定 seed。

引导必须成功读取规则集，要求完整的新鲜可见字段匹配投影，包括 `updated_at`，并独立强制覆盖配置前缀、无排除的已启用标签更新与删除保护。存在的 `bypass_actors` 必须是匹配证明的明确空数组；只有完全省略时才可使用证明值。Null、格式错误、可见字段缺失、投影变化、403 或网络失败均阻止执行，不触发回退。

例外仅适用于配置引导规则集的隐藏绕过字段。环境批准、不可变标签解析及确切运行与 seed 检查仍须实时验证。测试覆盖省略和明确空绕过、非空与 null 绕过、时间戳与规则及范围变化、缺失字段、错误仓库与规则集及管理员、证据字节变化、读取失败及尝试用于其他规则集或环境。

### 规则集时间戳表示

计算摘要或比较前，仅将投影中的 `updated_at` 规范化为 UTC。接受带明确偏移或 `Z`、小数秒为零至三位的有效 RFC 3339 日历时间戳。补齐毫秒，不舍入或截断。验证日历与偏移分量；拒绝无效日期、闰秒、未知偏移 `-00:00`、格式错误偏移及更高精度。规范输出为 `YYYY-MM-DDTHH:mm:ss.sssZ`，其他投影字段仍严格比较。

原始管理员响应字节及其证据摘要保持不变。引导和迁移的管理员及运行时投影使用相同规范化。重新生成并绑定派生投影摘要，摘要不匹配不触发旧格式回退。测试覆盖观察到的 `+08:00` 与 `Z` 等价、小数补齐、偏移跨日、一毫秒变化、无效输入及精度、其他字段变化和原始证据字节不变。

### 首次启用顺序与草稿权限探测

在迁移证据完整前保持首个机器人 PR 打开。验证实际机器人作者、最后推送者及所有者审查资格，完成限定草稿权限探测，保留并显式协调旧候选，禁用并排空旧写入者、撤销尚存权限，然后采集最终管理员预检及真实发布基线。此后保护或旧状态改变时必须刷新证据。

新不可变引导种子把最终报告、基线及摘要匹配的 `activation.active: true` 放入同一首个 PR。机器人最终提交使较早批准失效；所有者在普通保护下审查最终头提交。首次合并同时带入常规工作流与已验证启用，此后引导拒绝执行。证据不完整时保持 PR 打开；先合并未启用的中间版本会导致常规机器人无法准备启用 PR。

专用引导探测是引导禁止版本操作的唯一例外。维护者使用现有凭证，在确切不可变引导标签创建草稿预发布。经过审查的计划绑定仓库 ID、草稿 Release ID、标签及目标提交。单独获所有者批准的引导任务使用普通 `GITHUB_TOKEN`、发布权限声明及已审查不可变快照中的可信代码。

探测要求确切 Release ID、标签、目标及 `draft: true`。它上传名称唯一、内容固定且无害的资产，下载并验证摘要，再只删除该资产。它执行仅用于探测的正文编辑并恢复原正文。每次编辑保留 `draft: true`，不提供公开发布或改变目标能力。身份或字节冲突会阻塞，不能覆盖。中断只能针对相同身份和预期字节恢复。

结果记录工作流路径、不可变头 SHA、运行及尝试次数、声明 token 权限、Release ID 及完成操作证据。`preparedDraftTokenAccessVerified` 来自此成功结果，而不是只完成 GET。验收后维护者可移除探测草稿，受保护引导标签仍作为证据。测试拒绝公开 Release、错误 ID 与标签或提交、发布或更改目标尝试、字节变化及清理不完整。这只证明草稿操作，不证明生产执行、原生资格验证或发布。

## 通知与验收

机器人创建的采用 PR 提供普通 GitHub 通知。变更结果维护每个版本一个状态 Issue，包含候选与证据指纹、阻塞和下一步；内容相同则不编辑。任务摘要保持可用。在线 GitHub 与邮件送达在获准上线时验证，不能从生成 Markdown 推断。读取对暂时失败最多有界尝试三次；确定性阻塞和耗尽会停止。不引入定时变更重试。

测试覆盖真实 CLI 准备及机器人锁定最终提交、源码冲突与移动、改变工作流的采用、两份配置、试运行拒绝、架构不完整、陈旧批准、中断及不明确写入、缺少审查者、无权创建标签、准备取消、确切草稿发布、前序缺口、撤回与恢复及延迟旧任务。独立 QA 负责未变化候选的默认检查。实现产生真实准备载荷、未签名候选、基于测试数据的恢复及确切在线启用阻塞；公开创建版本要求批准该确切操作，签名发布仍保持阻塞。

## 自动发现与维护者通知

新增第四个工作流 `desktop-delivery-discover.yml`，每小时调度并支持手动派发。调度尽力执行，不保证送达时限。采用、验证和发布仍需显式启动，发现不会派发它们。

只读任务针对受保护 `main`、配置和已提交源码锁定执行完整有序发现，标识直接下一个版本或发现阻塞。后续排队版本不能绕过前序，也不会因同一个待处理前序而重复通知。

独立通知任务只有 `contents: read` 和 `issues: write`。工作流提交中的可信工具验证发现结果，为每个发行版创建或评论一个专用 Issue。候选代码和上游文字不在其 token 环境中执行。要求已启用替代流程并完成旧流程唯一写入者切换。在发行版专属通知并发组内重新读取启用状态，并验证检出的默认分支仍是最新提交；陈旧结果停止。未启用时只生成工作流摘要。

专用 Issue 使用稳定标题。正文或机器人评论说明下一个版本或阻塞、简要证据、运行链接和操作：把候选交给 Agent 准备并确认。绝不把上游版本称为可安装桌面更新。Issue 内容是通知历史，不是采用或发布权限。

语义指纹绑定发行版、结果、直接下一个版本身份、源码锁定摘要及稳定阻塞类别和资源，不包含时间戳、运行 ID、暂时诊断措辞和后续版本。在并发控制内比较最近的权威机器人通知。状态相同不创建、编辑、评论或重开。状态改变追加一次通知，Issue 不存在则创建。不明确写入先重新读取核对，再决定是否重试。人工关闭后，相同状态保持关闭；改变后的可行动状态可以重开并追加一次通知。

读取保留三次有界尝试。耗尽后，如通知可用则发送一次稳定阻塞通知，否则生成工作流摘要。后续调度只可重试发现读取，不能重试阻塞的采用或发布变更。恢复产生一次状态变化通知。GitHub 订阅和邮件设置控制送达；启用验收验证实际接收。本地实现不发送通知。

通过共享 GitHub 传输、验证和 Markdown 渲染接入 `notification-plan` 及通知应用。已启用的自动通知是逐次手动批准的有限例外，不能调用其他写入者。测试覆盖调度调用、未启用摘要、排序、多次运行状态相同不写入、后续版本抑制、阻塞与恢复通知、不明确写入核对、陈旧检出、并发去重、人工关闭、读取耗尽、两份配置，以及没有源码与发布变更权限或派发。在线上线单独证明送达及旧通知器已排除。

权威通知要求配置的不可变 GitHub Actions 用户 ID 及 API 的 `type: Bot`；登录文字、标题和 Markdown 不能证明身份。启用记录已验证机器人 ID。Issue 初始正文包含已验证的 `schemaVersion: 1`、`kind: desktop-discovery-notice`、仓库 ID、发行版 ID、结果、规范化发现状态及重新计算的语义指纹。评论标记还绑定所属数字 Issue ID。未知 schema 和不一致值会拒绝。

读取打开和关闭 Issue 的全部分页，排除 PR；选择机器人创建且初始标记有效匹配的 Issue。人工复制不能匹配，多重匹配会阻塞，匹配机器人证据畸形则要求修复。读取完整评论历史，只接受对该 Issue、仓库和发行版有效的机器人标记。按 API 创建顺序及数字评论 ID 选择最后通知，初始正文在前。获取不完整会阻塞变更。标题仅作展示。维护者编辑机器人内容属于管理员信任模型范围，不声称当前字节有密码学作者证明。

测试还拒绝人工复制的 Issue 与评论、不同数字 ID 的登录伪装、跨发行版或 Issue 标记、畸形机器人标记、分页缺失和重复 Issue；最后权威通知可能位于后续分页。
