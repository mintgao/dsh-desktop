## 评估与现行依据

保留 Electron、标准 DSH 启动器、共享 Web 客户端和随包运行时。[产品分层决策](../../.agents/notes/implemented/architecture/2026-08-25-downstream-client-product-layer.zh.md) 继续适用。进程管理和更新模块需要受支持的复用途径，并由配置提供 Mint 身份；模块位于应用内部说明复用尚有缺口，不能证明 Electron 导致发布失败。

[事务式采用决策](../work-items/20260831-upstream-mint-release-incident/technical-decision.zh.md) 在迁移前仍是运行依据。本提案改变源码采用与发布操作，不改变已安装应用。[调查记录](../work-items/20260908-desktop-distribution-redesign/brief.zh.md) 区分了历史合并、回调、初始化和包版本故障与当前审批阻塞。

## 拟议交付方案

分离发现、源码采用、产物验证与发布。保留整应用替换，应用内包含经过测试的 DSH 运行时和插件组合。不引入桌面侧 Git 合并、npm 更新或后端热替换。

**发现与采用。** 定时只读查询按仓库、Release ID、标签和解析后的提交识别上游公开版本。独立且权限受限的写入身份为每个版本创建或更新一个普通采用 PR（Pull Request），没有合并、发布或签名权限。标签解析结果变化时阻止采用。保留按序采用与交付；跳过版本不在本决策内。维护者在分支保护下解决冲突并批准工作流改动。合并源码不触发公开发布。

**产物验证。** 使用冻结依赖，从同一个确切已合并下游提交构建两种 Mac 架构。发布 manifest（元数据清单）记录桌面与 DSH 版本、上游与下游提交、构建工作流提交、运行及尝试编号、插件版本、架构、预期文件和摘要。高成本构建前断言下游 workspace 版本一致。重新检查实际合并提交；合并前测试不能授权另一棵源码树。

候选执行不持有发布或 Apple 凭证。签名版本通过单独受保护的任务，用可信打包工具处理已验证载荷；持有凭证时绝不运行候选脚本、hook 或应用二进制。签名和公证后记录最终摘要；无凭证任务对这些确切最终文件运行安装冒烟验证。产物缺失或过期必须重新验证并批准。

**确认发布。** 两种架构通过安装验证后，维护者批准最终 manifest 摘要，适用时包含最终签名和公证字节。一个受保护环境中的发布运行展示并绑定该摘要、源码提交、验证运行及尝试编号。可信发布者检查绑定、仓库、工作流身份、验证成功、完整性和摘要。源码、字节、manifest、签名或验证尝试变化都会使批准失效，必须重做受影响验证并重新批准。创建或验证不可变桌面标签，上传草稿，验证全部草稿文件，公开发布，再获取并验证公开结果。不一致时撤回并显示阻塞。每个版本用一个 Issue 记录失败与恢复。

发布重试不重新执行源码采用。仅当 manifest 相同、文件精确匹配时续传中断草稿；冲突文件或标签会终止尝试。已验证的公开版本视为幂等成功。绝不覆盖已发布版本；不同构建需要新的桌面版本。PR、工作流产物和 Release 提供记录；不再要求源码、标签与可变队列 ref 之间的原子事务。

## 按序推进

迁移建立经过审查的基线，记录最后验证的上游身份、桌面标签和最终 manifest 摘要。每个采用 PR 更新已提交的源码锁定记录，包含上游仓库、Release ID、发布时间、标签、提交和前序上游身份。受保护 Git 历史保留早期记录。采用按发布时间选择下一个公开版本，时间相同则按 Release ID 排序。不能绕过未解决的采用。发现意外更早版本，或已记录上游身份变化、缺失时，必须核对处理。

每个最终 manifest 指明源码锁定记录，以及前序桌面标签和 manifest 摘要。只有公开文件匹配 manifest，且前序关系可追溯到基线时，交付才完成。每次确认发布前重新检查公开证据。下一个发布必须匹配最后已验证交付之后的直接后继源码记录；更晚采用的提交不能绕过它。不需要单独完成记录 PR 或可变队列 ref。

发布、撤回和恢复共享一个仓库级变更并发组，不取消运行中的任务。获得执行资格后，重新读取源码记录、标签、Release 和 manifest。相同发布请求进行幂等核对；后续版本等待或阻塞，直到前序验证完成。草稿不算完成。文件或前序记录缺失、身份冲突、后继关系不一致都会阻止推进。

撤回将版本与 manifest 保留为草稿，并阻止后续发布，直到恢复或为相同上游版本验证替代产物。替代产物使用新桌面版本，记录被替代标签与摘要，并指向撤回前的有效前序。已发布后继仍是历史证据，但恢复未解决时不能授权继续发布。删除已记录前序关系会阻止核对，绝不静默移除前序。本机制对照保留的源码记录、manifest、标签和基线检测变更，不检测发现前已删除的版本，也不声称能检测管理员协同重写全部证据。

## 信任与产品选择

建议采用 GitHub 分支、标签和环境保护，加上维护者明确确认发布，替换三个自定义 App 和定期到期的签名策略证明。保留最小权限、工作流审查、候选执行无秘密、隔离签名、不可变标签和独立发布权限。发布者没有绕过分支保护的权限。GitHub 无法限制为仅操作 Release 的写权限，是由分支和标签保护约束的剩余风险。

仓库管理员成为发布信任根；替代方案不以密码学方式认证 GitHub 隐藏配置。保护配置变更需要审查和验证运行。所有者已接受替换独立签名策略证明，记录于[所有者确认](#owner-confirmation)；当前控制保持生效，直到切换经过验证。所有者接受由 Agent 辅助准备与执行、维护者确认的方式，以及由此产生的发布时间依赖。按序交付版本保持不变。

维护者通知覆盖可决定采用的升级、可处理的阻塞，以及可公开发布的合格产物。使用 GitHub 通知，邮件是否发送取决于接收者设置；实现时必须验证实际送达。通知概述变化、证据、建议和相关 PR 或候选。所有者可以把链接交给 Agent，授权具体合并或发布，无需手工 Git 经验。本流程不假设 GitHub 事件会唤醒 Codex 对话，也不自动授权未来外部操作。

## 桌面复用与用户体验

只抽取已有明确用途的可复用行为：具有显式接口和资源释放机制的后端管理及原生更新生命周期。Electron 提供原生适配器；Mint 提供品牌、应用身份、发布仓库和经过验证的默认值。测试使用不同配置的第二个最小桌面组合、适用时的外部打包安装、通用 Web 不包含 Mint 默认值，以及 Mint 依赖闭包。仅移动文件不构成验收。

保留原生更新菜单；本次不要求新增应用内面板。未来任何 DSH Client 更新 UI 都归插件所有，通过范围明确、具有类型定义的原生能力接入，不得导入 Electron 或获得任意文件与命令访问。普通用户只看到一个客户端更新、桌面版本、面向用户的更新摘要和安装选择。默认流程不提供独立 DSH 或插件更新渠道，不要求用户决定组件版本。DSH 与插件版本保留在发布元数据中，供维护和排障使用。只有可安装桌面版本才触发普通用户更新提示。后台检查失败保持安静；手动检查显示可恢复错误和经过验证的发布页面。

保留未签名预览版的手动安装，以及由用户控制的签名稳定版下载与重启。只有架构与渠道兼容且完整公开的版本才是候选。元数据或签名无效时阻止安装。替换前关闭后端，绝不热替换活动会话。摘要可以检测字节变化，但不能证明未签名预览版的发布者身份。

## 数据与失败恢复

整应用替换不证明数据可安全降级。产物验证记录可读持久格式、迁移以及旧应用能否重新打开新数据。共享 DSH home 必须考虑其他 DSH 进程；备份或迁移不能与其他写入者竞争。不兼容版本需要经过单独审查的独占访问备份恢复流程和恢复证据，否则阻止发布。新数据写入后不承诺自动二进制回滚。

离线检查和下载失败保留运行中的应用。启动失败保留日志与用户数据，并提供恢复说明。撤回阻止未来发现，但不能降级已安装副本。恢复必须区分文件替换失败与新运行时已经写入不兼容数据。

桌面发布维护者负责采用阻塞、发布核对、撤回和恢复。每次调用对已分类的暂时网络或服务错误最多尝试三次，使用有界退避和有限超时。认证、缺少批准或证据、身份或摘要冲突、数据不兼容及验证失败立即阻塞。尝试耗尽后停止，不自动派发另一工作流；调度不恢复已阻塞变更。每个版本用一个 Issue 指出阶段、证据摘要、原因和纠正动作。相同阻塞既不重复变更，也不编辑或创建 Issue。纠正后，维护者通过版本身份和预期 manifest 摘要明确恢复，或恢复采用 PR。恢复重新验证证据与批准；已完成发布只核对，不重新构建。

## 迁移

1. 完成所有者选择和独立审查；只读保存当前控制器状态、活动 PR、标签、Release 和凭证身份。
2. 运行替代发现与产物验证，不对采用 PR、分支、源码锁定记录、标签、Release 或 Issue 进行远程写入。输出拟执行动作并验证两种架构。证明失败构建可恢复；旧自动化仍是唯一远程写入者。
3. 暂停旧发现、采用和发布调度；禁用所有变更入口，包括延迟 Observer 回调和派发。等待任务结束或取消，并撤销变更凭证，然后才能启用任何替代写入者。验证延迟回调无法变更。保留状态 ref 为证据，并合并包含确切活动版本和已验证基线的迁移输入。排他检查通过后才启用替代采用与发布；不跳过或重建已发布版本。
4. 通过替代流程发布一个试验版本。验证下载、安装、启动、数据保留和后续发现。保留公开 URL、预览版发现稳定版的路径及桌面版本单调递增。
5. 试验版本验收后才退役旧身份、策略证明和状态设施。对旧决策交叉链接，并仅替代已迁移的职责。

公开发布前，回退须恢复有效旧前提，且只保留一个发布者。替代流程发布后，恢复旧流程必须先审查并核对该版本；绝不启用竞争发布者或静默重置游标。

## 备选方案

**保留事务式自动化。** 保留无人值守交付与独立配置证明，但继续承担跨工作流恢复、续期和多身份依赖。仅当这些保证值得相应运维成本时适用。

**替换 Electron。** 需要重新验证原生行为，却不能解决已观察到的采用和发布故障。现有证据不支持它。

**单独更新后端。** 增加外壳、后端与插件协商，以及独立信任和迁移恢复。较小下载量不足以证明这些需求值得承担该复杂性。

**使用固定版本上游包。** 可能减少源码冲突，但必须先证明已发布运行时闭包和下游插件兼容性。记录不可避免的上游改动及其贡献或移除路径；拆分仓库属于单独迁移，不是修复交付的前提。

## 验收

测试重复发现、标签身份变化、源码冲突、workspace 版本不一致、单架构失败、过期批准、签名来源不可信、中断草稿上传、重复确认发布，以及公开摘要不一致与撤回。验证离线与手动检查、无效架构和元数据、未签名预览版替换、签名更新验证、后端关闭、不兼容数据及安装中断。每个场景必须对应观察证据；静态和单元检查不能证明原生安装或生产权限。结果由工作项验证记录持有；这些是尚未执行的实现要求。

还须测试并发确认发布、阻塞或撤回的前序、缺失或冲突的前序关系、成功发布后验证中断、签名或重新验证导致批准失效、只读试运行拒绝 PR 和分支写入、延迟旧回调、重试耗尽、相同确定性阻塞及明确恢复成功。

验证仅 DSH 变化、仅桌面变化以及两者共同变化时，都只提供一个客户端更新流程，不要求组件选择。验证采用就绪、阻塞和合格待发布产物的维护者通知送达，以及仅发现上游版本但没有可安装桌面版本时，不向普通用户提示更新。
