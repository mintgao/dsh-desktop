# 已审核的追赶采纳与桌面发布

Status: Accepted

[English](20260910-desktop-catch-up-delivery.md) | 中文

## 范围与权限

[工作项](../work-items/20260910-dsh-015-upgrade/brief.zh.md)记录了所有者批准一次追赶升级 PR 和一次桌面发布，覆盖完整中间上游区间。本决策扩展[已审核交付决策](20260908-desktop-reviewed-delivery.zh.md)。固定目标为 `dsh-v0.1.5-alpha.2`；后续发布不改变目标。合并与发布仍需分别批准。

Phase A 在 `scripts/desktop-delivery/`、CLI 接线、工作流、测试和规范文档中实现可复用证据与验证。发行身份仍由配置拥有。Phase B 按已安装策略准备上游应用变更；原生所有权和数据迁移需要各自的决策与资格认定。Phase A 不启用签名、不合并上游源码、不修改已安装数据，也不增加写入者。

可信工作流代码负责外部验证和变更。候选代码不持有写入凭据。现有保护、机器人作者身份、有实质内容且仅修改锁的最终提交、不可变标签、受保护发布批准和有界重试保持不变。桌面交付维护者负责失败与恢复。

## 显式选择

在 `upstream`、`desktop` 和 `replacement` 之外增加 `catch-up`，保留现有类型语义。`adoption-plan --kind catch-up` 要求 `--target-tag` 和 `--target-commit`。完整发现按发布时间及 ID 排序，绑定目标发布 ID、标签、提交和发布时间，以及从当前锁之后到精确目标之间的每个配置选定版本。

追赶要求至少两个版本；单个后继使用 `upstream`。拒绝缺失或未推进的目标、错误提交、不完整观察和冲突身份。不得替换为最新版。定时发现与通知保留紧邻后继行为，不能授权采纳。严格位于固定目标之后的新发布不使其区间失效。

## 源码与评估证据

源码锁 schema 3 保留 schema 2 字段并要求 `catchUp`，值为 null 或 `{ schemaVersion: 1, from: Release, to: Release, releases: Release[], assessment: { path: string, sha256: string } }`。其 `from` 等于前驱；`to` 等于当前版本。版本列表与观察身份中的精确有序区间 `(from, to]` 一致，不得遗漏、添加或重复。

读取器在原已允许的位置接受历史 schema 1 和 2。生产最终提交要求 schema 2 或 3 种子绑定。新的最终提交输出 schema 3；普通推进将 catchUp 设为 null。同上游桌面准备、替代发布和人工修复后的重新最终提交在重新绑定种子时逐字节保留现有追赶证据。拒绝旧 schema 中的追赶字段和未知 schema。不得重写历史锁或清单。

带版本且已提交的评估绑定精确起点、终点和范围身份，为每条相邻版本边提供评估，并单独评估从基线到目标的直接升级。它记录持久格式变化、不支持的降级、兼容性发现、仓库相对证据路径及内容摘要，以及已验证、受阻或未验证的场景状态。评估与引用必须是受包含约束的普通文件。拒绝自引用、源码锁引用、环、逃逸路径和被修改的字节。证据文件是叶子，不递归解释为评估。审核和受保护批准提供权限；评估元数据本身不能证明人工批准或直接升级安全。

## 准备与机器人最终提交

规划绑定范围、当前锁摘要、精确受保护基线、显式目标、桌面版本及已验证交付基线身份。保留从目标派生的分支命名和待处理 PR 检测。初次追赶要求源码基线与已交付上游基线一致；待发布的源码推进是谱系阻塞。

准备在保留的隔离检出目录中，将精确目标合并到精确下游基线。验证基线和每个选定上游提交均为目标祖先，且目标仍在种子祖先中。非祖先区间会阻塞，不使用合成合并、挑选提交或省略身份。冲突需要经审核解决。种子包含评估及引用证据；拟议锁保持分离并绑定种子提交和树。版本与依赖检查不持有凭据。

任何机器人写入前，最终提交独立验证 schema、范围、评估、精确受保护主分支与基线祖先关系及前锁摘要。它获取完整实时观察并重算区间，拒绝目标之前或目标位置的缺失、变化或新插入身份，检查每个提交的祖先关系，并从精确种子读取评估与引用字节。目标之后的新发布仍可接受。夹具完整性不是实时权限。

保留种子与树绑定、单父且仅修改锁的变更、机器人身份、远程头相等性以及非强制更新。在现有并发控制下，于变更前立即重新检查当前主分支与分支。匹配重试不写入。人工变更要求新种子及有实质内容的最终提交；范围或评估变化要求新的已审核计划。

## 资格认定与发布

生产清单 schema 2 要求从规范化锁证据复制 catchUp，或设为 null。其摘要绑定的包包含评估及所有引用证据，并具有精确文件清单。读取器保留 schema 1 历史支持，但不授予追赶权限。

对于追赶，清单与锁目标必须匹配；实际已验证公开桌面最新交付或已激活旧版基线必须匹配 range.from 和 lock.predecessor。要求完整区间及直接升级证据，不得伪造中间桌面清单。普通 upstream 保持紧邻后继；desktop 与 replacement 保留同身份与已撤回末端规则。同上游修复和替代发布保留追赶来源记录，但不再次推进。

一致更新所有消费者：releaseManifest、checkedManifest、verifyFinalization、verifyQualification、verifyDelivery、保留包、撤回身份及前驱遍历。任何路径都不得静默丢弃区间证据。发布规划、维护者标签及草稿准备、发布者都须在写入前独立重新验证实时区间和交付末端。身份或范围变化、已撤回前驱、清单变化或远程移动均会阻塞。资格认定与批准始终绑定字节。

撤回可以隐藏精确标识的受损发布。恢复验证保留的精确发布与祖先证据；它不是新的采纳。保留精确字节恢复、替代限制和不支持降级规则。

Phase A 保留生产资格认定对 persistedFormatsChanged 为 true 的现有拒绝，直到存在单独审核的迁移资格认定。追赶发布要求已验证的基线到目标直接升级兼容性，不能仅凭边清单或全新安装冒烟测试。受阻或未验证评估不能获得资格。不得对用户真实 DSH 主目录测试，也不得声称自动降级安全。

## 可信部署与恢复

首先通过旧可信 desktop 类型准备及最终提交流程，在现有上游身份上准备策略或工具 PR。必要检查与所有者合并将新工具安装到受保护主分支；不发布桌面版本。然后基于该新主分支准备唯一实际追赶升级 PR，由新可信工具完成最终提交。目标合并、原生资格认定和精确批准先于一次桌面发布。

工具 PR 是前提，不是中间上游采纳或产品发布。可以提前准备离线目标预览，但不能用旧工具完成最终提交。不得使用历史引导例外、将目标代码标记为仅桌面变更，或用持写入凭据的候选工具执行。

策略合并前，保留现有策略和种子即为恢复方式。一旦存在 schema 3 证据，须保留兼容读取器或停止写入者；旧工具无法验证它。已发布证据保持不可变，并使用已接受的撤回与恢复机制。

## 验证

测试实际 CLI 入口。拒绝缺失目标参数、错误或缺失目标、未推进目标和单版本追赶；不完整、重复或冲突观察、遗漏、错误区间顺序、身份变化或插入发布；非祖先区间、伪造前锁或过期基线；缺失或被篡改评估、缺失边或直接证据、路径逃逸、环或摘要不匹配；schema 2 中的追赶、未知 schema 或空证据；过期种子、分支或树变化、非仅锁最终提交和远程移动。

拒绝清单与锁区间不一致、错误或非最新及已撤回基线、缺失或被篡改区间资产、受阻或未验证兼容性、未经资格认定的格式变化、不完整原生架构、过期批准、资格认定后的实时区间变化、候选编排、引导复用，以及持写入凭据执行候选。包含七版本成功、目标之后的新发布、不写入重试、中断草稿续传、人工重新最终提交、追赶后的普通推进、同上游修复、已撤回末端替代、精确恢复和历史 schema 支持。

RD 负责聚焦检查；独立 QA 对未变化 Phase A 候选的完整配置验证负责，并执行一次。Phase B 需要单独就绪确认和验证。夹具证明编码行为；真实所有者审核资格、原生资格认定和发布仍需独立证据。

## 备选方案与决策证据

改变普通 upstream 语义会使跳过成为隐式行为。合成中间锁会掩盖实际采纳与交付。候选控制最终提交会削弱可信主分支权限。显式类型和版本化证据保留可检查性，不增加控制器、账本、权限类别或定时写入者。
