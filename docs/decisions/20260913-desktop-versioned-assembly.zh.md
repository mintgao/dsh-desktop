## 版本化输入

Desktop 包含三个分别标识的输入：官方 DSH 运行时闭包、本地打包的 Mint 扩展和 Mint Electron 外壳。用户只接收一个 Desktop 版本。

通过经审核的源码采用，将开发源码同步至上游 `fb2c4b9e698e30edb738bca4cf0618587db7d203`。运行时只使用官方 npm 产物，从 `@deepseek-ai/dsh@0.1.5-rc.2` 开始。源码祖先关系不能证明已安装产物身份。CLI 产物完整性为 `sha512-8Xc8hCQHcIWRmTCVU/xZdp6/qMsWMeAd2ObChKDEsfhUPJFXx6H0lgeb1DxUMD86HZrrVN+1bCvn1ppjZ/fOxw==`。

完整的冻结锁记录传递依赖与平台选择的精确版本、解析位置和完整性。组装还记录 Mint tarball 摘要和外壳身份。构建获取步骤只下载记录的产物并核验完整性。启动不执行安装、注册表查询或工作区后备解析。

在现有后端准备入口中替换源码全量打包。安装官方冻结闭包后，仅在未占用的软件包位置加入明确的 Mint 内容，并拒绝冲突。随后不得运行可能替换官方依赖的无约束安装。缺失的 Mint 运行时依赖需要额外锁定输入。允许共用安装目录；独立来源记录和实际解析结果证明分离，而非目录名称。

上游清单、profile 和可执行内容保持原样。核验内容、受限链接、原生及客户端资源。单独记录安装生成的必要文件。新阶段通过验证之前，保留此前完整阶段；准备中断时必须保留它，或明确使构建失败。

## Profile 与扩展加载

在现有 DSH home 下保留 `desktop-mint`。首次初始化通过 RC.2 支持的 profile 设施，在用户补丁前依次选择 Base、Web 和 Mint Bundle。Mint Bundle 包含配置；通知插件拥有可释放的行为。

RC.2 提供 `--from-default-profile web`、`dsh.profile.bundles`、公开 profile 初始化工具、安装与 profile 查找，以及所选 bundle 的依赖投影。真实产物测试必须证明解析和客户端加载。创建参数仅使用一次，绝不能无条件传给现有 profile。

原生初始化拥有独占操作和可恢复的完成状态。涉及多次写入的初始化记录它拥有的精确文件与预期内容。恢复只完成能够明确识别的输出；有歧义的目录必须以具体诊断失败。部分完成的 Web-only profile 不能被视为 Mint 初始化已完成。

保留现有清单、自定义 bundle 顺序、补丁、锁文件和依赖，不重置现有 profile。检查必需软件包的实际解析，避免冲突的用户软件包静默替换已证明的组件；保留冲突文件并报告不兼容。任意第三方覆盖不属于验证范围。

## Desktop 接口

- 启动使用已验证的 CLI 路径、现有 home、所选 profile 与工作目录，明确指定 Electron Node 模式及固定回环参数。
- 就绪处理读取官方公告，仅为导航在内存中保留令牌，并证明真实认证准入。拒绝格式错误、非回环和不支持的输出；日志与显示的诊断隐藏查询值。
- 关闭区分启动失败、正常退出和意外退出；终止等待进程关闭，并测试升级终止信号。
- 原生集成保留沙箱渲染、同源导航、外部链接策略与 Web Notifications。原生代码不推断 Agent 或 Session 语义；可复用 Client 插件不导入 Electron。

打包发布拒绝 CLI 路径替换；打包模式不可使用开发覆盖。保留临时端口策略。不引入跨源浏览器状态迁移或未签名通知保证。

## 兼容与恢复

支持精确的已安装 RC.2 闭包。验证打包的 Mint Host 与 Client exports，不使用源码别名；同时验证不含 Mint 默认项的独立纯 Web 组合。原生代码不转换会话或替换数据根目录。分别测试现有合成 profile/数据与首次安装。备份或恢复前等待测试进程停止，单独保留升级后的数据。应用替换不授权降级读取。

## 发布证据

保留 source-lock、祖先关系、激活、配置和发布验证检查。source-lock 目标和实际 CLI 都必须标识 RC.2。工作区组件枚举属于开发源码证据；从暂存安装中枚举运行时组件，并将组件及组装输入摘要绑定到发布验证和发布元数据。同步更新生产者与验证者。绝不以工作区版本替代已安装版本，也不只是移除相等性检查。

Desktop 和 DSH 版本即使相同也有各自含义。历史记录保持原样。缺失或过期的组装证据阻止发布验证。远程发布、机器人最终确认和已安装应用替换不属于本实施任务；准备精确候选供正常最终确认，不虚构机器人来源证据。

## 替代方案与归属

从源码构建混合运行时无法满足未修改产物的验收。修改官方清单会重建 CLI 耦合。启动时安装插件会为离线启动增加网络和包管理器状态。采用上游私有 Desktop Host 会改变未签名行为、传输及 profile 归属，超出范围。延后开发源码同步需要独立重新设计采用来源记录，也没有必要。

Mint 构建和原生工具拥有组装检查、初始化和进程监督；上游拥有运行时及数据格式；Mint 插件拥有功能行为。独立 QA 拥有最终验收。缺失官方依赖、公开扩展不可用，或任何修改官方字节的需要，都必须重新开启本决策。

## 必需证据

AC-1/2 需要冻结的官方安装、明确的 Mint 打包、内容/解析/链接验证，以及缺失软件包、冲突和篡改的负例。AC-3 除解析失败外，还需要真实官方 CLI 的就绪、认证和进程生命周期。AC-4 需要外部 Host/Client 加载与纯 Web 组合。AC-5 需要隔离的 arm64 打包 UI、无密钥会话和退出。AC-6 需要首次/现有/中断 profile 场景及实际组件元数据。AC-7 需要实际执行耦合检查，并将更新的常设策略连接到现有打包调用方。本设计记录不声称任何测试结果。
