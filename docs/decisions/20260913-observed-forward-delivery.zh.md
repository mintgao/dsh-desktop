# 通过观察验证的 Apple Silicon 向前交付

[English](20260913-observed-forward-delivery.md) | 中文

状态：已接受

## 范围与权限

本次交付遵守[已批准的 A 到 B 范围](../work-items/20260911-desktop-update-path/forward-baseline-scope.json)和 [Apple Silicon 范围](20260913-mint-arm64-scope.zh.md)。A 是经过认证但未发布的 0.1.5-alpha.2.unsigned.1 基线；B 为 0.1.5-alpha.2.unsigned.2，内含 DSH 0.1.5-alpha.2，发布前必须检查标签未占用和版本顺序。真实发布前驱与不可变的追赶评估保持不变。历史持久化格式变更仍为 true。本决定取代[能力探测](20260913-forward-native-capability.zh.md)中的 Intel 和云端 Accessibility 前提，不取代其保留的诊断证据或隔离义务。

未签名 Desktop 检查发布并打开浏览器。获取核验、停止应用、手动替换和恢复属于操作员步骤；本次不增加自动安装器，也不承诺客户端核验下载完整性。[受审核发布器](20260908-desktop-reviewed-delivery.zh.md)保留激活、精确源码锁定提交、不可变标签和明确发布环境批准。

## 证据负责人

受保护 CI 负责精确源码、组件身份、arm64 打包、原生冒烟测试和完整构建清单。操作员负责私有安装与状态目录、认证输入和手动操作。QA 记录直接的普通桌面观察及其限制。记录审核者不声称自己亲自观察。校验器检查固定身份、必需场景和恢复不变量。维护者通过现有受保护发布计划签认精确的本地记录。本地记录明确标为 `maintainer-attested-local-observation`：哈希证明字节完整性，CI 证明构建来源，两者都不证明 GUI 操作发生。单一维护者可以批准这种有限证据，无需第二位 GitHub 维护者。

## 构建包与最终包

向前评估使用 schema 2 和明确的向前策略描述符，不能同时携带历史迁移策略。历史 schema 1 保留原有行为。向前策略固定 A 的源码、版本、构建归档、DMG 和运行时身份、arm64、声明设置及固定场景清单。生产者、本地消费者和发布器共用兼容性分派器，拒绝未知版本或冲突证据。

资格工作流从干净且完成锁定的候选只构建一次，输出 `build-receipt.json`，purpose 为 `desktop-forward-build`，包含精确仓库、发行、配置、候选、源码锁、评估和策略身份、工作流提交、运行和尝试编号、B 版本和组件及完整文件描述符。归档包含 DMG、原生报告、候选、评估、策略、说明和前驱证据。它不包含 GUI 资格证据，不能直接发布。历史评估保留原有迁移分支。

观察这些精确字节后，纯组装器生成 schema-3 最终清单与发布包。它绑定构建记录、工件清单和本地观察，并固定 `publicDelivery: pending`，不包含未来的发布变更运行身份。现有批准计划绑定其摘要和实际发布变更运行。公开验收另存为绑定清单摘要的记录，绝不改写已冻结资格。重新构建或改变工件使已有观察不能复用。

## 本地观察记录

单个版本化 UTF-8 JSON 文档，解码后不超过 32 KiB，记录发布前阶段、arm64 主机、操作系统、会话和权限事实、观察者身份、方式与时间、构建记录摘要、A/B 工件和运行时身份、声明的私有根目录与同路径安装身份、固定动作、结果、来源和状态，以及恢复和清理状态。任意附件、可执行脚本、配置目录内容、凭据、原始日志或任意截图不得进入发布包。仅本地保留的辅助材料不得被描述为发布器验证过的输入。

每个必需场景恰好出现一次且通过：工件身份；私有状态和进程所有权；A 普通启动、设置、退出和重开；静止且完整的 pre-B 备份；停止后的同路径替换；B 普通版本、界面、无密钥操作、退出和重开；声明设置保留；获取失败和重试；操作员拒绝错误字节；替换权限拒绝和恢复；不完整备份拒绝及包含 A 普通启动观察的完整恢复；自有进程和挂载清理。不接受不适用豁免。可以引用精确的既有 A 可用性证据，避免重复付费对话。失败演练使用独立私有副本，不伪造通知，也不把操作员决定描述为产品自动拒绝。

## 发布器接入

向前发布为现有变更工作流增加规范 base64 编码的本地观察字节及其 SHA-256。输入通过环境变量传入，不插入 shell 代码。严格解码、限制大小并拒绝畸形或不匹配输入。历史操作不需要观察记录；下架和恢复拒绝无关的新观察输入。

只读计划阶段认证完整 CI 构建归档及实际成功运行，校验本地记录，重新组装清单并比较请求的精确摘要。批准摘要明确说明，批准同时表示接受该精确本地观察作为有限人工验收，并授权指定发布操作。现有发布变更包和批准计划在既有 mint-publication 环境批准前保留这些字节。执行阶段重新检查计划、运行、环境和文件。

schema-3 发布仅将构建所属文件与 CI 归档比较；派生清单和本地观察由发布变更包与获批计划绑定。恢复验证保留的完整最终包，在新的恢复批准下重新认可原始观察，不刷新历史日期。下架保留较窄的身份检查，避免观察证据缺失阻止撤下发布。本设计不授权具体 B 发布；精确观察和对外发布包仍需所有者批准。

## 恢复与限制

替换前，停止所有自有应用和 backend 写入者，验证完整 A 应用及声明私有状态的备份。未改变的 A 必须在失败后正常重开。如果文件或数据已改变，先停止写入者，单独保留 B 修改后的状态，验证备份完整性，恢复 A 和 pre-B 状态，再观察 A 普通启动、可用界面、保留设置和普通退出。绝不启动 A 读取 B 修改后的数据。仅哈希相同不能证明恢复可用。

不确定的进程所有权、未完成的 LaunchServices 提交或中断的恢复会阻止验收并保留目录。不得无限重试、悄悄删除不确定目录，或在启动完成尚不明确时根据空进程清单推断已停止。同一症状连续两次修正失败后，报告证据并停止该诊断路径。

## 实施与验证

使用三个有界模块：forward-evidence 校验固定策略和观察；compatibility-evidence 分派版本；forward-package 生成构建记录并确定性组装最终包。扩展既有 CLI、清单、发布器和资格及变更工作流。不引入 GUI 运行器、自动安装器或通用恢复框架。完成源码审核和实质性源码锁定提交后，再进行一次 B 构建。

测试保留历史语义，拒绝缺少、重复或失败场景，伪装为 CI 的观察，错误身份或架构，被修改的归档字节，超限输入，缺少恢复后 A 观察，不确定清理，不一致组装和改变的已批准记录。构建成功但没有人工验收时拒绝发布。明确批准的预览可以在公开交付仍为 pending 时发布。保留包恢复和不依赖完整证据的下架有专门回归覆盖。真实发布前和公开 A 到 B 操作仍是分别观察的验收条件。
