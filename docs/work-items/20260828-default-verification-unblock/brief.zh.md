## 目标

恢复通过的完整默认 Vibe 验证回执，同时保持仓库当前已经记录并发布的官方工作流隔离与 Shell 超时行为不变。

## 背景

第一次具备主机能力的默认验证通过了 lint、typecheck 和 build，但暴露了四项测试失败。`scripts/ci-workflow.spec.ts` 中三项断言早于提交 `8b2e684bcb` 有意加入的官方仓库 guard。另一个 `tool-bash` 集成断言假定捕获超时信号后总会以零退出，但文档约定是独立报告超时与最终进程状态，而 macOS 进程树最终返回了 143。完成这些修正后，两次全量测试暴露了相关沙箱竞态：由调用方终止的后台进程也可能以 143 结算，但后台拒绝分类只检查退出码，因此即使句柄的权威状态是 `killed`，只要 stderr 命中签名仍可能被误判。这些行为失败解决后，类型感知 Oxlint 项目发现契约在单独运行时用时 2 至 4 秒，但在全量套件十个 worker 争用下两次超过 20 秒预算，分别用时 22.652 秒与 26.787 秒。

## 范围

- 范围内：让静态工作流测试与现有官方仓库 guard 对齐；让真实 Bash 超时测试断言跨平台一致的超时事实；让后台沙箱分类遵守现有的已终止进程状态；为类型感知 Oxlint 项目发现契约提供有界的全量负载预算；更新适用决策的验证说明与本工作项证据。
- 范围外：工作流 YAML、进程终止机制、超时或渲染格式、沙箱策略或 runner 行为及无关清理。

## 设计与技术说明

- 保持 Mint 下游仓库禁用官方工作流；不得削弱或移除仓库 guard。
- 保持独立报告超时、信号与退出状态。真实进程测试不得对安装 TERM trap 的进程树最终如何退出作出跨平台保证。
- 在两个逐调用镜像的沙箱执行器中，都将后台句柄已有的 `killed` 状态视为拒绝与 runner 失败分类的权威依据；不得改变子进程层的终止或进程报告方式。
- 超时校准仅限于加载 Host 与 Client TypeScript 项目图的 Oxlint 契约。60 秒上限超过已观测全量负载耗时的两倍，同时仍能发现真实挂起。
- 只保留一名实施写入者，并在聚焦检查通过后执行独立 QA。

## 风险与未决事项

- 过宽的工作流断言可能放过未加 guard 的任务；应枚举所有受约束的工作流并检查每个任务。
- 过度削弱 Bash 断言可能不再证明超时标记；保留超时标记的正向断言，并保留零退出的纯渲染用例。
- 终止可能与自然结算竞态。仅当执行器已将句柄标记为 `killed` 时抑制沙箱失败分类；普通非零退出仍必须保留保守的拒绝与 runner 失败匹配。
- 过宽的超时增长可能隐藏 Oxlint 回归。其他契约测试继续保持 20 秒，仅多项目类型感知发现使用有限的 60 秒上限。
