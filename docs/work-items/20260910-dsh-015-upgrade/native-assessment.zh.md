# 原生集成与迁移评估

[English](native-assessment.md) | 中文

## 状态

这是 `upgrade_native_assessment` 提出的 Phase B 指导，比较基线 `132ab869cbb800e1bf236efbaabfd4668fb3c67b` 与目标 `b2e3b2a0125854567a4a5fcba75782e42fe84901`。本评估不包含应用启动或访问用户数据。实现前需要单独的 Accepted 决策、独立审核和就绪确认。

## 原生所有权提案

将 Mint 的 Web-profile 原生适配器保留在 `apps/desktop-mint`，同时保留上游 `apps/desktop` 和 `apps/desktop-host`。保留 Mint 应用 ID、品牌、desktop-mint profile、浏览器状态身份和手动更新偏好。目录迁移不得改变持久化身份。

上游拥有保留桌面 profile、帧式管道传输和签名打包假设。Mint 使用经过认证的环回启动和独立版本的未签名预览。直接替换会引入额外 profile、来源、权限和插件管理变化。避免含混共享主进程、整体替换上游或立即采用上游外壳。

Mint 必须继续通过受支持的 `dsh` profile 路径启动。Bundle 负责选择和默认值，可复用插件负责行为，原生模块负责生命周期。打包依赖闭包和精确运行时兼容性需要测试。保留上游签名验证，并将任何未签名例外限定为 Mint 专用。

## 迁移提案

使用上游会话格式目录和冻结的 V0→V1→V2→V3 边。原生代码不得转换会话数据。分别评估读取打开行为与持久写入打开发布，并保留来源字节。设置、凭据、profile 和其他持久存储需要覆盖七个版本的独立完整清单。

通过组合后的列表、读取、恢复、关闭和重新打开场景，测试可丢弃基线主目录与已发布历史夹具。记录原始摘要、不可变后继发布、中断写入恢复、来源漂移和异常输入拒绝。仅列出头部不能证明完整恢复。检查标题、工作区、继承、压缩、引用和通知行为。

手动恢复需要静止状态的可丢弃备份，并单独保留较新数据。替换应用文件不能恢复可读数据。自动降级或删除较新代次既未获授权，也不作此声明。

## 尚需证据

Phase B 需要 Accepted 原生决策、独立审核、完整持久存储清单、已设计的迁移资格认定以及组合和打包测试。原生 arm64/x64 闭包、后端启动、清理、导航及手动更新需要验证。依赖签名的通知行为仍未验证。Phase A 工具验收不满足这些要求，也不授权合并、发布或替换已安装应用。
