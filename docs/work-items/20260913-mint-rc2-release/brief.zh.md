## 授权与范围

用户授权发布、同步 GitHub 主页与换机交接信息、确认发布后替换本机 Desktop，以及清理过时的中间应用产物。保留用户数据、原来有未提交改动的开发目录和需保留的发布证据。清理仅覆盖已明确识别的中间构建，不包括源码改动、已公开版本或无关应用。

## 验收

- 在现有政策归属文档中记录版本化组装与扩展归属要求，并连接项目入口要求与交接文档。
- 通过现有机器人流程确认精确 RC.2 源码祖先，验证精确的未签名 arm64 发行版，并核对公开标签、清单、资源内容与安装。
- 发布后才同步双语主页，提前准备文案。交接信息说明权威源码、版本化输入、构建与发布流程、本地数据及恢复归属，不包含凭据或私人机器状态。
- 停止已安装应用，保留完整恢复副本，安装经过身份核验的公开产物，再观察正常启动与用户数据保留。成功后仅删除属于本次操作的过时产物，替换验收前保留一个恢复副本。

## 技术就绪

[已接受的组装决策](../../decisions/20260913-desktop-versioned-assembly.zh.md)及其[独立评审](../20260913-desktop-versioned-assembly/technical-review.zh.md)继续约束相同的组件身份和原生职责。发布准备 CLI 仍将 Mint 包归入官方源码版本检查；直接执行已复现它拒绝 Mint 独立版本的问题。局部修正该调用方，使其遵循已接受的组件拆分，保留对不一致官方包的拒绝，并给真实 CLI 测试夹具添加独立 Mint 版本。不提出新的运行时架构。此局部一致性修正达到 implementation-ready；流程编排者负责确认和唯一写入，保留独立 QA。现有宿主专家任务数量限制使之前的 RD 无法恢复。

## 工作区版本一致性

真实采用准备通过了发布家族检查，但工作区清单检查仍将两个精确 Mint 目录强制设为官方根版本。将已接受的独立版本规则也应用于该检查器，共用既有的精确目录清单。保留其他所有清单、发布检查和官方包版本拒绝。通过真实清单检查器测试不同 Mint 版本，并拒绝位于其他目录的同名包。不改变运行时或发布权限。独立 Tech Lead 已批准此有界适用性。门禁负责人：root；implementation-ready。检查器变化使此前完整候选验证失效；修复后进行最终 QA。

## 按平台选择的可选依赖

使用 npm 11.19.0 的 Linux x64 与 macOS arm64 发布 CI 拒绝缺失的 `@emnapi/runtime`；它只能经由被平台排除的可选 WASM 父依赖到达。本地 npm 10 保留该孤立依赖。独立作者证据与审核已批准管理决策中的平台选择澄清。此前就绪与完整验证不授权、也不验证此组装检查器变化。

修复必须依据冻结的官方依赖图与安装选择，区分合法的平台裁剪可选后代与缺失的必需或已选包。保留冻结身份检查和每个已安装官方包的逐字节比较。覆盖嵌套解析、共享必需可达路径、循环、包含 Linux libc 的平台选择器、已选载荷缺失与可选载荷篡改。不得接受所有缺失可选包或放宽启动收据检查。此修复不授权改写运行时包、迁移用户数据或改变发布保护。一名 RD 负责实现，root 负责门禁；独立 Tech Lead 作者、审核者与 QA 分别负责证据。通过既有机器人重新最终确认修正后的 seed，再验证精确产物。
