## 切片边界

范围内——通道接缝的提供方角色，面向腾讯 iLink Bot API（`https://ilinkai.weixin.qq.com`）：

- 扫码登录序列：取码、轮询扫码状态、过期刷新，并把最终令牌经 `ctx.credentials` 写入。
- 连接生命周期：可观察状态（`idle | connecting | connected | unavailable`，后者带诊断）、令牌锁、长轮询，以及断开行为。
- 入站路径：在持久游标下的 `get_updates`；每条更新经认证、规范化后，作为私聊会话发布到通道事件。
- 出站路径：带分块的 `send_message`、平台限流策略，以及消费方记录所需的收据。
- 重试与熔断：轮询与发送的经校验界限，以及在被限流平台前报告 `unavailable` 而不是空转的熔断器。

范围外，并标明各自由哪个切片负责：

- 消费方（绑定、授权、投递记录、命令、中继）——M1 已落地；命令与中继属于 M4。
- `packages/api/channel-controller` 与客户端设置区（含二维码渲染）——切片 M3。本切片把登录操作暴露在提供方注册面上，供该页面消费。
- Mint bundle 行、`MINT_PACKAGES` 与打包检查——切片 M5。
- 群聊与媒体。仅私聊、仅文本：消费方发送 agent 的最终回复文本，附件属于阶段三，入站富媒体在说明书范围之外。媒体路径的约束（AES-128-ECB 用 `node:crypto`）已记录在决策中，供加入它的切片使用。
- 企业微信、公众号与非官方协议——不在本功能范围内。

## 包形态

`packages/channel/channel-weixin/` 是一个 Host 插件包，注入 `channels`，并全部经 `ctx.effect` 注册；它不声明任何第三方运行时依赖，因为 `verifyMintPackages` 会把每个声明的依赖解析到冻结的官方闭包内。

| 文件 | 职责 |
|---|---|
| `src/index.ts` | 插件本体：校验过的 `Config`、提供方注册、生命周期状态与拆卸 |
| `src/login.ts` | 扫码登录序列与向 `ctx.credentials` 的令牌写入 |
| `src/transport.ts` | 基于 Node 内建能力的 iLink HTTP/JSON 调用与错误映射 |
| `src/poll.ts` | 长轮询：游标、重试界限、退避与熔断器 |
| `src/send.ts` | `send_message`：分块、限流策略与收据 |
| `src/lock.ts` | 令牌锁文件：独占创建、心跳与陈旧规则 |
| `src/normalize.ts` | 把平台更新转换为通道的入站事件 |
| `src/types.ts` | 仅类型，无运行时代码 |

建包流程遵循[新增包的 cookbook](../../cookbook/adding-a-package.zh.md)：两个 tsconfig 汇总文件里的登记、`channel/` README 配对中的一行、插件形态所需的 `package-reference` README 形式、重新生成并手动跟随中文侧的 config catalog，以及 doc 图谱中 `channels` 角色的提供方列表（其中会列出本包）。

## 持久状态

本切片不新建 storage domain。它的持久面：

- 平台令牌：经 `ctx.credentials` 写入，永不回到客户端。
- 令牌锁文件：按平台身份落在配置的锁目录中；崩溃会留下陈旧锁，由下一个实例按陈旧规则接管。
- 轮询游标：存放在 M1 的绑定记录中——本包在启动时读取已持久化的游标，并把当前游标随每条入站事件交给消费方；由消费方在与接纳同一笔写变换中持久化。

## 登录序列

1. 提供方注册面上的 `beginLogin` 取得二维码并报告等待状态。
2. 轮询扫码状态，直到返回已扫码、已确认或已过期；过期即取新码，序列始终只有一个有效二维码。
3. 确认后得到令牌，经 `ctx.credentials` 写入，并报告登录创建的 bot 身份。
4. M3 的页面渲染这一序列；本切片的真实验收改用一次性脚本渲染二维码。

## 入站序列

1. 获取令牌锁；若另一实例持有，报告 `unavailable` 与诊断，而不是轮询。
2. 解析令牌；未存有令牌时，报告需要重新扫码的状态。
3. 以配置的超时从游标开始轮询 `get_updates`。
4. 映射平台错误：会话过期（`errcode -14`）停止轮询并报告需要新扫码的状态；瞬时失败在配置界限内重试；连续失败打开熔断器，报告 `unavailable` 与诊断。
5. 认证并规范化每条更新：会话、发送方、消息 id、文本与游标；群聊会话不发布。
6. 发布到通道事件；消费方在接纳该消息时持久化游标。

## 出站序列

1. `send(conversation, message, signal)` 把正文按配置的分块长度切分，并按序发送各分块。
2. 被限流或瞬时失败的分块在配置的界限与延迟内重试，并遵守中止信号。
3. 平台接受全部分块后，调用以首个分块的消息 id 解析；否则以平台诊断拒绝。

## 配置

每个界限都是一个必填且经校验的 `Config` 字段——硬编码常量不构成可配置性。API 基址保持为协议常量，不是字段。

| 字段 | 含义 |
|---|---|
| `pollTimeoutMs` | 长轮询超时 |
| `pollRetryAttempts`、`pollBackoffMs` | 轮询重试的界限 |
| `sendRetryAttempts`、`sendBackoffMs` | 发送重试的界限 |
| `throttleDelayMs` | 被限流发送在重试前的延迟 |
| `breakerThreshold` | 打开熔断器所需的连续平台失败次数 |
| `chunkLength` | 平台长度上限内的出站分块长度 |
| `lockDirectory` | 令牌锁文件所在目录；Mint bundle 指向桌面数据目录 |

## 本切片应交付的证据

- 以脚本化传输替身驱动的按模块单元测试：登录状态机及其过期刷新、锁的独占创建/陈旧接管/被取代持有者、轮询循环的游标、`errcode -14` 与熔断器、发送路径的分块/限流重试/收据，以及规范化的私聊过滤。
- **一个经 Loader 的真实组合测试**：在脚本化传输替身上装配提供方，断言登录序列推进、轮询把一条规范化消息发布到通道事件，且发送按分块切分并解析出收据。
- **一次真实平台往返（由所有者参与）**：一次性脚本渲染二维码；所有者扫码、发送一条私聊消息，并观察到回复回到微信。在 M5 完成桌面装配之前，这是唯一能看到真实往返的方式。
- 针对本包源码的逐文件 100% 覆盖率，用聚焦的覆盖率命令运行。
- README 配对、分组 README 行、重新生成的各类目录，以及 `pnpm run doc-sync`。

## 工作顺序

1. 包骨架、各项登记，以及传输模块与其测试。
2. 登录序列、凭据写入，以及令牌锁与其测试。
3. 轮询循环、错误映射与规范化。
4. 发送路径及其分块与限流策略。
5. 组合测试，随后是真实往返脚本，然后是文档产物与 `doc-sync`。

## 已记录的本地假设

- 游标恢复：由于一条 token 级流喂给所有会话，提供方从各绑定中最旧的游标续 poll；重复由 `lastAdmittedMessageId` 抑制。
- 收据携带首个分块的消息 id；投递记录仍以整条回复为单位，而非按分块。
- 提供方只发布私聊；群聊会话被忽略并记录一行诊断。
- 锁文件持有者的心跳每个轮询周期刷新一次；陈旧阈值是配置轮询界限的两倍。
- 令牌的凭据名由本包固定；设置文档只携带引用。

## 本切片的风险

- **iLink API 是官方的，但没有公开文档**，错误码与限流语义以参考实现为准；真实往返是与平台核对这些的地方。
- **锁的陈旧规则在硬杀之后要付出等待**：崩溃持有者的心跳停摆，下一个实例须等过陈旧阈值才能接管。等待会以诊断报告，而不是藏起来。
- **传输必须能在没有平台的情况下测试**，而基址保持为协议常量；替身在传输接缝处注入，具体机制（模块替身或构造注入）在实现时按仓库惯例选定。
- **游标把本包与消费方的 domain 耦合**：提供方按名称读取绑定 domain；若该读取不可用，则在实现所需之处补一个读取口。
- **真实往返需要所有者参与**扫码与发消息；它无法在 CI 中运行，因此本计划把它作为带证据记录的手动验收步骤。
